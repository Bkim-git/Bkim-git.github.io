### 4 November 2026 – [[DfW v1.4.1 (early release), latest]](https://github.com/Bkim-git/DfW-algorithm)

#### Local and transect analysis
The depth map showed the result but not the evidence behind it, so a doubtful depth could not be traced back to its spectra or modes. Right-clicking the map now shows, at that point, the modes in the f-k plane over the video's power with the dispersion relation, the pixel intensity spectrum and the propagation direction; along a transect, it shows depth, celerity and nonlinearity. The first analysis no longer loads the DMD libraries.

#### Package size: 217 → 170 MB
A list of the largest files in the 512 MB program folder showed duplicated and unused components:
- NumPy and SciPy each shipped their own OpenBLAS. SciPy now comes from conda-forge, linked to NumPy's OpenBLAS, so one library runs under one thread setting.
- The PROJ database was bundled three times: pyproj's own, rasterio's, and conda's, which pyproj's PyInstaller hook collects on Windows because it checks paths with "/". DfW now points `PROJ_DATA` to pyproj's database, which rasterio also reads, and the other two copies are dropped.
- OpenSSL, Tcl/Tk and the AVIF image codec were included although DfW uses none of them. They are excluded by file name, since Qt's hooks still collected the OpenSSL DLLs after Python's `ssl` module was excluded.

The algorithm reference was regenerated: depths differ from 1.4.0 by at most 5e-13 m (median 1e-14 m), with NaN in the same places. The program folder is now 432 MB.

#### Inversion memory
The inversion converted the resampled video to floating point and copied it again for masking. It now keeps the video in its 8-bit type, a quarter of the float copy, and masks it without a copy; results are unchanged. A float video stored as a read-only memory map, which failed with masking off, is now copied into an owned array.

#### GUI-only distribution
The command-line program `DfW-cli.exe` is still built for testing but is no longer distributed, so the release has a single entry point.

### 27 October 2026 – [DfW v1.4.0 (early release)]

#### Graphical user interface
Running DfW meant editing `config.yaml` and running scripts in sequence. The full workflow, from video processing to depth mapping, now runs in a single Windows application with step-by-step guidance, interactive result viewers and project files that store every setting and intermediate product.

#### Integrated video preprocessing
Video import, rectification, GCP tracking, georectification and co-registration were separate scripts, so raw video needed external tools before depth inversion. They are now steps of the same workflow.

#### Standalone distribution
DfW required a Python installation with a matching set of scientific packages. The program is now built with PyInstaller and runs offline. With NumPy linked to Intel MKL, the first build was 842 MB; switching to OpenBLAS reduced it to about 507 MB, and the example depths differ from the MKL results by a median of 1.3e-5 m. OpenBLAS's default thread count stalled under CPU load, so DfW caps it at the number of physical cores before NumPy loads. A tutorial project, a user manual and a reference copy of the processing source are provided with the release.
### 30 December 2025 – [DfW v1.3]

#### (Optional) Ground-truth validation
A validation step is executed when ground-truth data are available in the input directory (automatically skipped otherwise).

#### (Optional) DMD visualization
Mode-wise wave propagation videos derived from DMD can be generated in `.mp4` format to visualize spatial wave patterns, controlled via the `flag_show_DMD` switch.

#### Persistent runtime logging
All console outputs produced during execution are saved to a `.log` file for post-run inspection and reproducibility.

### 24 December 2025 – [DfW v1.2]

#### Process-level parallelization redesign
The depth inversion workflow has been redesigned for process-level parallelism, enabling efficient mode-wise and point-wise estimation on multi-core systems via `joblib`. Core routines in `modules` have also been refactored to be stateless, so parallel workers share no mutable state.

#### Shared-memory–based data exchange
Intermediate data are exchanged through shared memory with read-only access, reducing memory overhead and inter-process communication while ensuring safe parallel execution.

### 11 July 2025 – [DfW v1.1]

#### Nonlinear wave correction
Introduces a dedicated module to account for wave nonlinearity, improving depth inversion accuracy, particularly in shallow water and energetic wave conditions.
Reference: [Kim et al., 2026](https://doi.org/10.1016/j.coastaleng.2025.104904)

#### Adaptive interrogation windowing
Automatically adjusts the optimal size and shape of the interrogation window with respect to global bottom slope, and local wavelength and direction.
Reference: [Kim et al., 2025](https://doi.org/10.1080/21664250.2025.2469957)

#### Input and configuration handling
The input interface has been streamlined by supporting standard video formats (e.g., `*.mov`, `*.mp4`) instead of compressed NumPy archives. Spatial referencing is now decoupled from the video and provided via an external `extent.txt` file, while all runtime parameters have been consolidated into a standalone `config.yaml` file, removing hardcoded dependencies.

#### Visualization and reference data support
Visualization capabilities have been enhanced with optional satellite image overlays via `basemap.png`. In addition, ground truth inputs now support both raster-based formats (e.g., GeoTIFF) and point-based formats (e.g., `*.csv`, `*.xyz`), enabling more flexible validation and comparison workflows.
